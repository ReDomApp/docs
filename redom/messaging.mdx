The messaging domain is implemented through a family of route modules and database schemas rather than one route file.

## Core capabilities documented by the backend README

- Direct and group conversations.
- Conversation inbox and message history.
- Attachments, media and encrypted media envelopes.
- Message drafts, read receipts and reactions.
- Forwarding, shared messages, link previews and chat information.
- Group details, invite permissions, approvals, reports and send guards.
- Scheduled group calls and linked-device links.
- End-to-end encryption and conversation cryptography.
- Message lifecycle/completion handling.

## Data model

The database directory includes conversations, conversation participants, messages, attachments, message reads, drafts, message requests, deletions, media envelopes, group invite links, and scheduled group calls.

## Security boundaries

Encryption-related routes are mounted under the messages router. The repository contains separate E2EE and conversation-cryptography modules. Encrypted media has separate handling from ordinary attachments. Do not infer cryptographic guarantees, key custody, device synchronization semantics, or recovery behavior without reviewing the corresponding implementation and tests.

## Route modules

The registry includes `messages.routes.ts`, `message-media.routes.ts`, `encrypted-media.routes.ts`, `messaging-e2ee.routes.ts`, `messaging-conversation-crypto.routes.ts`, forwarding and shared-message routes, drafts, read receipts, inbox, chat info, group details, approvals, group reports, permissions, send guards and linked-device routes.

## Operational cautions

Message state may distinguish accepted, sent, delivered, read, deleted, failed, and moderated states. Do not equate API acceptance with recipient delivery. Per-user deletion and everyone deletion are distinct behaviors. Document actual state transitions from service code and tests before publishing detailed sequence diagrams.
