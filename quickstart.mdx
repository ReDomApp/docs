## How the documentation is organized

Use the product navigation to move from a system overview into its API routes, data model, security design, and operational details. ReDom is the central backend application; Aurelink is integrated into that backend, while ReDom Mail, ReDom SMS, ReDom Intelligence, and GPU workers have separate service boundaries.

## Source verification

For implementation details, inspect the current `ReDomApp/redom-backend/main` branch:

- Route registry and route modules define mounted HTTP interfaces.
- Controllers and services define request behavior and business rules.
- Drizzle schema modules and SQL migrations define persistent data structures.
- Tests establish the behavior they actually exercise.
- Package manifests and deployment manifests describe build and deployment intent.
- Live provider and infrastructure state is required to claim operational availability.

## Status vocabulary

| Status | Meaning |
|---|---|
| Implemented in source | Code for the behavior exists in the current branch |
| Configured | Runtime configuration exists or is documented; live operation may still require verification |
| Partial | Some parts exist, but the complete workflow is not present or verified |
| Planned | Explicitly described as future work |
| Unverified | Available evidence does not establish current behavior |

## Documentation update process

1. Compare changes in the master repository with the previous documented source revision.
2. Identify affected products, route modules, schemas, services, and deployment files.
3. Read the relevant source and tests; do not infer an API contract from filenames alone.
4. Update the affected pages in `ReDomApp/docs`.
5. Validate internal links, navigation, and technical claims.
6. Publish the docs change only; never deploy application code as part of documentation work.

Automatic push-triggered documentation workflows are not active on the current Mintlify Hobby plan. Until a supported workflow is enabled, this update process requires an authorized documentation run.
